02 — PRODUCT OVERVIEW

产品概述

Transit 是一款面向应届生求职者的 AI Agent 产品。用户粘贴目标岗位的招聘 JD（岗位职责 + 任职要求），AI Agent 自动完成以下工作：

  1. JD 拆解：从任职要求中提取 3 个最核心的能力维度
  2. 资源搜索：调用 GitHub Search API 和 HuggingFace API，搜索与每个能力点匹配的真实开源项目和公开数据集
  3. 项目生成：基于搜索到的真实资源，生成具体到"今天就能写第一行代码"的作品集项目建议
  4. 路线可视化：以地铁线路图的形式呈现 3 条能力路线，每条路线包含 JD 原文依据、项目名称、具体做法、证明逻辑、参考资源、预估耗时
核心价值主张：把 JD 从"看不懂的门槛"变成"走得通的路线图"。不是告诉用户"你需要学数据分析"，而是告诉用户"用这个 Kaggle 数据集 + 这个 GitHub 项目，2 天内做出一份带运营建议的分析报告"。

产品定位

用户群应届生 / 零项目经验的求职者
使用场景看到心仪岗位 JD → 不知道怎么准备 → 粘贴 JD → 获得可执行方案
核心动作粘贴 JD → 生成路线 → 复制项目卡片 → 开始动手
替代方案手动搜索"怎么准备XX面试" → 碎片化信息 → 无从下手
差异化不是"AI 帮你写简历"，而是"AI 帮你做简历上该写的内容"
03 — BACKGROUND & PROBLEM

背景与问题定义

3.1 用户研究基础

本产品的需求来源于 VoiceMap 模块的真实用户声音采集。通过 WebSearch + WebFetch 从牛客网、知乎、V2EX、小红书四个平台采集了 108 条真实求职者发言，经 AI 主题聚类归纳为 7 大痛点：

# 痛点类别 提及量 占比 与 Transit 的关系
1投递无反馈 / 石沉大海2321.3%间接 — 通过提升简历竞争力改善投递转化率
2简历质量差 / 与 JD 不匹配1917.6%直接 — Transit 的核心切入点
3求职焦虑 / 心态崩溃1715.7%间接 — 可执行路线降低"不知道做什么"的焦虑
4面试表现差 / 准备不足1614.8%间接 — 做完项目即面试素材
5缺少实习 / 项目经历1513.9%直接 — Transit 生成的就是项目经历
6学历门槛 / 双非困境109.3%间接 — 用作品集弥补学历短板
7信息差 / 求职渠道单一87.4%直接 — Transit 从 JD 倒推能力需求，消除信息差

Transit 直接命中 3 个核心痛点（#2 简历与 JD 不匹配、#5 缺少项目经历、#7 信息差），间接覆盖另外 4 个。

3.2 问题定义

PROBLEM 核心问题

应届生看到心仪岗位的 JD 时，面临三重困境：

  1. 看不懂：JD 里写的"具备数据分析能力""熟悉大模型原理"——不知道具体要做到什么程度
  2. 做不到：知道要学什么，但不知道从哪开始、用什么资源、做什么项目
  3. 证不了：学了东西，但没法在简历和面试中证明"我确实会"
INSIGHT 产品洞察

现有求职工具（简历优化、面试题库、AI 模拟面试）都在解决"怎么包装自己"，但没有人解决"包装的东西从哪来"。应届生缺的不是简历模板，而是简历上该写的内容本身——真实的项目经历。

Transit 的切入点：不帮用户写简历，而是帮用户做出简历上该写的项目。每个项目都与 JD 一一对应，做完即可直接写入简历。

6.2 核心功能详细规格

F-01 JD 双输入框 P0
  • ①
    双输入框设计 「岗位职责」和「任职要求」分为两个独立 textarea，引导用户完整粘贴 JD 两部分内容
  • ②
    输入提示 每个输入框下方有 hint 文案：「粘贴岗位「岗位职责 / 岗位描述」部分的完整文本」「能力点提取优先来源于此部分，请尽量完整」
  • ③
    校验规则 两个输入框不能同时为空。「任职要求」为空时给出 toast 提醒但允许继续（降级模式）
设计决策：为什么不合成一个输入框？因为「任职要求」部分信息密度远高于「岗位职责」（前者写能力标准，后者写工作内容），分开输入让 AI 能区分优先级，优先从任职要求提取能力点。
F-02 Agent 自动分析 P0

系统通过 Agent 模式（非单轮对话）完成 JD 分析：

  • ①
    能力维度提取 从 JD 中提取恰好 3 个最核心的能力要求，优先来自「任职要求」部分。不多不少——3 条是"选择不瘫痪"的最小有效集合
  • ②
    JD 原文引用 每个能力点必须引用 JD 原文中最能体现该要求的一句话（≤30 字），让用户明确"这个项目对应 JD 哪句话"
  • ③
    Agent 迭代控制 最大迭代 8 轮，建议 4 轮内进入总结阶段。防止 Agent 陷入无意义重复搜索
F-03 / F-04 资源搜索（GitHub + HuggingFace） P0

Agent 自主调用两个外部工具搜索真实资源：

工具API搜索对象返回字段每次返回
search_github GitHub Search API 开源项目仓库 name, stars, description, url, language Top 5（按 stars 排序）
search_datasets HuggingFace API 公开数据集 id, downloads, likes, url Top 3
容错策略：如果 search_datasets 连续 2 次返回错误或超时，Agent 自动放弃该工具，基于已有的 GitHub 资源继续生成建议，不反复重试。
F-05 项目卡片生成 P0

每个项目建议包含以下结构化字段（JSON 格式）：

// 单个项目卡片数据结构
{
  "skill":        "能力名称",
  "jd_quote":     "JD 原文节选（≤30字）",
  "project_title": "项目名称",
  "project_brief": "具体做什么，产出什么形式",
  "why_it_proves": "为什么能证明该能力（1-2句）",
  "estimated_time": "预估耗时（如 2-3天）",
  "references": [
    { "name": "资源名称", "url": "链接", "type": "github|dataset" }
  ]
}
  • ①
    恰好 3 个项目 不是 1 条（太窄）也不是 5 条（选择过载）。3 条提供低/中/高投入三种路径，用户可选适合自己时间节奏的方案
  • ②
    具体到可执行 项目建议必须具体到"今天就能开始写第一行代码"，不能是"学习数据分析"这类空泛表述。必须包含具体工具、数据来源、产出形式
  • ③
    证明逻辑闭环 每个项目都有 why_it_proves 字段，说明"为什么做完这个项目就能在面试中证明该能力"，形成 JD → 项目 → 简历 → 面试的闭环
F-06 地铁线可视化 P0
  • ①
    地铁线隐喻 把"准备过程"可视化为地铁线路：START（应届生/零经验）→ 3 个站点（能力项目）→ END（作品集就绪）。降低"不知道走到哪了"的心理焦虑
  • ②
    三条线路色系 L1 红色 (#E15A42)、L2 绿色 (#1D8F80)、L3 橙色 (#E5A23A)。每条线路有独立色系，卡片顶部有对应色条
  • ③
    站点动画 站点圆点依次弹出（弹跳缓动），卡片从右侧滑入。垂直连接线从上到下展开。动画延迟随站点序号递增（0.3s + i * 0.35s）
F-07 Agent 思考过程展示 P1

通过 SSE（Server-Sent Events）流式展示 Agent 的推理过程，增强透明度和信任感：

事件类型含义展示内容
thinkingAgent 思考模型输出的推理文本
tool_call调用工具工具名称 + 搜索关键词
tool_result工具返回搜索结果列表（Top 3）
final生成完成最终 JSON 结果
error执行错误错误信息
设计意图：展示 Agent 思考过程不只是"炫技"。它让用户看到 AI 确实在搜索真实资源（而不是编造），增强生成结果的信任度。同时可折叠设计避免信息过载。
F-09 Demo 降级模式 P1
  • ①
    自动降级 当 API 不可用（网络错误 / 未配置 Key / 超时）时，自动加载预置的 Demo 数据并展示，toast 提示"无法连接 AI 服务，当前为 Demo 模式"
  • ②
    手动 Demo 页面提供独立 Demo 按钮，用户可一键体验效果无需填写 JD
  • ③
    Demo 数据质量 预置 3 条完整的示例项目（AI 产品实操、数据分析洞察、SQL+Python Pipeline），结构与真实生成结果完全一致

工具层

8.2 Agent 工作流程

Transit 采用两阶段 Agent 架构：

  1. 阶段一：Agent 循环 — 模型接收 JD → 自主决定是否调用工具 → 执行工具搜索 → 获取结果 → 继续推理 → 输出自然语言总结。最多 8 轮迭代，建议 4 轮内完成
  2. 阶段二：JSON 格式化 — 将阶段一的自然语言总结输入第二个 Prompt，低温（0.3）格式化为严格 JSON 数组。如果解析失败，自动修复一次
为什么两阶段？Agent 模式擅长"搜索 + 推理"，但不擅长"输出严格格式"。拆成两阶段后，阶段一专注内容质量，阶段二专注格式规范，两者各司其职，成功率显著提升。
