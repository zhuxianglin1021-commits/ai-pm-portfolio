01 — PROBLEM DEFINITION

为什么做这个项目？

从目标用户的核心矛盾出发，定义产品机会

⚠

用户痛点

应届生投递 AI/产品岗位时，JD 上要求「数据分析」「SQL」「用户研究」「A/B 测试」等能力， 但不知道做什么项目、怎么写进简历、如何证明自己匹配。 投 50 份简历没回音，却不知道问题在哪。

→

产品机会

把 JD 从「门槛」变成「路线图」。 用 AI 帮助用户把任职要求翻译成可执行的项目计划， 再用诊断工具验证简历匹配度，形成「分析 → 执行 → 验证」闭环。

CORE INSIGHT
缺的不是能力，而是把能力翻译成行动的方法。AI 应该把 JD 的模糊要求，转化为用户今天就能开始的具体任务。

05 — AI APPLICATION STRATEGY

AI 应用策略：不只是调用 API

为什么用 Agent Loop + Function Calling，而不是单次大模型调用

AI DECISION 01

从「单次问答」到「Agent 循环」

如果只用大模型生成项目建议，结果可能是编的。 我让 AI 自己决定什么时候搜索 GitHub、什么时候搜索数据集、 什么时候停止搜索开始总结，保证每条路线都有真实资源支撑。

产品价值：解决大模型「幻觉」问题，让 AI 输出可落地、可验证。
AI DECISION 02

SSE 流式反馈，降低等待焦虑

Agent 循环需要多轮 API 调用，等待时间可达 10-20 秒。 我用 SSE（服务器推送事件）把每一步思考过程实时显示给用户， 让用户感知到 AI 正在工作，而不是卡住了。

产品价值：把「黑盒等待」变成「透明过程」，提升用户信任感。
AI DECISION 03

两阶段输出：先思考，再结构化

第一阶段让 AI 自由发散，生成自然语言的项目建议； 第二阶段用低 temperature 强制格式化为严格 JSON， 保证前端能稳定渲染。兼顾创造性与结构化。

产品价值：避免 AI 输出不稳定导致前端崩溃，提升可用性。
AI DECISION 04

浏览器端解析，保护隐私

Screen 的 PDF / DOCX 解析放在浏览器端完成， 简历文本不上传服务器。在满足功能需求的同时， 降低用户对隐私泄露的担忧。

产品价值：隐私优先设计，提升用户上传意愿。
06 — PRODUCT DESIGN · VALIDATION

Screen：像安检一样逐项扫描简历

诊断工具的设计逻辑：把模糊焦虑变成具体行动

Screen · 简历 X 光机

把「不知道差在哪」
变成「知道补什么」

简历被拒的原因往往是隐性的。Screen 从 JD 的两个维度逐项扫描简历， 用直观的视觉符号告诉用户：哪些匹配、哪些部分匹配、哪些完全缺失。

  • ①
    双维度匹配：分别检查「岗位职责」和「任职要求」，避免只看关键词
  • ②
    三色信号灯：绿 / 黄 / 红 一目了然，降低认知负担
  • ③
    隐私优先：浏览器端解析文件，不上传服务器
  • ④
    可执行建议：每个缺失项都给出具体改进方向，不只是打分
